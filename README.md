# 리서치 맵

여러 증권사 리서치 리포트를 모아 테마와 산업별로 시장의 흐름을 살펴보는 개인용 대시보드.

![리서치 맵 홈 화면](docs/images/home.png)

## 왜 만들었나

그룹포탈에는 매일 많은 리서치 자료가 올라온다. 모두 읽기에는 시간이 부족했고,
읽어도 핵심을 정리하기가 쉽지 않았다. 궁금했던 것은 “매수”, “매도”라는 의견보다
그 의견에 이르는 논리였다. 무엇이 달라졌고, 왜 그렇게 보는지 알고 싶었다.

리서치 맵은 증권사 보고서를 요약하고, 여러 보고서를 테마와 산업별로 묶어 시장의
흐름을 보여준다. 개별 보고서의 세부 내용과 시장 전체의 흐름 사이를 오가며 읽는 도구다.
애널리스트의 정보가 이미 주가에 반영돼 있더라도, 배경을 이해하는 일이 시간이 지나며
도움이 될 것이라는 생각에서 시작했다.

```text
리포트 원문 → 요약·분류 → 테마·산업별 종합 → 주간·일간 흐름 → 대시보드
```

## 무엇을 볼 수 있나

- **일간 다이제스트**: 오늘의 한 줄과 핵심 3개를 쉬운 말로 읽는다.
- **홈·주간 인사이트**: 테마 지도와 주간 흐름, 테마별 증권사의 시각을 살펴본다.
- **테마·산업**: 관심이 몇 주에 걸쳐 어떻게 변했는지, 어떤 산업에서 나온 이슈인지 확인한다.
- **리포트 상세**: 핵심 포인트와 변화·의미·확인할 점을 읽고 원문으로 이어간다.
  AI 논리 평가는 근거에서 결론까지 이어지는 논리의 강점과 약점을 짚는다.
- **숫자 변화**: 리포트 속 투자의견·목표주가·실적 추정치·컨센서스를 종목별로 쌓고,
  방향과 속도가 크게 바뀐 지점(목표주가 급변, 연속 조정, 속도 가속, 추정치·컨센서스 급변,
  컨센서스와의 괴리, 산업 리비전 방향 전환)을 이벤트로 표시한다. 종목 페이지에서 목표주가
  추이와 추정치 이력을 본다.

![리포트 상세 화면](docs/images/report.png)

매수·매도 추천이나 목표주가 예측은 하지 않는다. 시장의 흐름을 이해하고 공부하기 위한
도구이며, 투자 판단의 근거로 삼기 위한 것은 아니다.

## 현재 범위와 한계

하나증권·미래에셋증권은 원문 사이트에서, 메리츠·유안타·SK·유진·대신·IBK·상상인·LS·한화·iM은
한경 컨센서스에서 받는다 (`config/sources.json`). 삼성·NH·KB·한국투자·키움·신한처럼 두 곳 어디에도
공개 목록을 올리지 않는 증권사는 아직 없다. 리서치 보고서의 매수 의견 쏠림은 그대로 이어질 수 있어
AI 논리 평가로 보완한다. 실적 추정치·컨센서스 표는 아직 하나증권 양식에서만 읽는다.

수집·요약·분류, 리포트별 인사이트, 주간 인사이트·산업 브리핑·일간 다이제스트,
대시보드와 AI 논리 평가, 투자의견·목표주가·추정치 변화 추적까지 구현했다. 변화 추적은
리포트가 나온 날만 관측되므로 듬성듬성하고, 지금은 하나증권 한 곳의 시각이다. 처리량 증가에
따른 비용·저장 구조 정리는 앞으로의 과제다.

## 동작 방식

상시 서버 없이 GitHub Actions로 수집·가공 작업을 실행하고, 결과는 git 커밋으로 남긴다.
`main`에 커밋이 올라오면 Vercel이 대시보드를 다시 빌드한다.

1. **새 리포트 수집** — `daily-pipeline`

   평일 한국 시간 17:47에 하루 한 번(정각을 피해 GitHub 예약 지연을 줄임) 켜 둔 소스(하나증권·미래에셋 리서치 게시판, 한경 컨센서스)에서
   새 리포트를 수집한다. 일반 브라우저 헤더로 요청 간격을 두고, 로그인 없이 공개된 목록과 PDF만 받는다.
   PDF는 메모리에서 텍스트만 추출한다. 추출한 원문은 `raw-text` 브랜치에, 메타데이터는 main에 커밋한다.
   한 소스가 막혀도 나머지는 계속 받는다.

2. **요약과 종합** — `process-reports`

   수집이 성공하면 리포트를 요약하고, 리포트별 인사이트와 산업·테마 태그를 붙인다.
   같은 테마의 이름을 합친 뒤, 그 주 리포트가 2건 이상인 산업의 브리핑을 만든다.
   이어서 숫자 변화를 다시 계산하고(LLM 없음), 새 이벤트에만 리포트가 밝힌 변경 이유를 붙인다.
   요약은 실행당 최대 100건, 최신 리포트부터. 산업 브리핑·주간 인사이트·일간 다이제스트는 한국 시간
   17시 이후 실행에서 만든다. 그 전에 돈 실행(수동 등)은 날짜만 `data/index/publish_pending.json`에 모아 둔다.
   수동 실행이면 시각과 상관없이 바로 만든다. 자동으로 다시 만드는 범위는 최근 7일이라, 과거 리포트가
   늦게 들어와도 지난 날짜의 다이제스트는 그대로 둔다(필요하면 `redo_date`로). 요약은 최신 리포트부터 한다.

3. **대시보드 갱신** — Vercel

   커밋이 올라오면 대시보드를 다시 빌드한다. 로그인 후 최신 결과를 볼 수 있다.

4. **선택한 리포트 평가** — `evaluate-reports`

   리포트 상세에서 “AI 평가” 버튼을 누르면 그 리포트만 Opus로 논리를 평가한다.
   평가 결과를 커밋하면 대시보드가 다시 빌드돼 화면에 반영된다.

- 각 단계의 규칙은 `skills/*/SKILL.md`에 있고, 이 파일을 프롬프트에 그대로 넣어 따르게 한다.
- LLM은 Claude Code CLI(`claude -p`, 도구 비활성화)를 로그인 토큰으로 호출한다.
  파이썬 스크립트가 파일 입출력을 맡고, LLM과는 텍스트만 주고받는다.

PDF는 내려받아 메모리에서 텍스트만 추출하고 버린다. 수집·가공 결과는 데이터베이스 대신
저장소의 JSON·Markdown 파일로 관리한다. 증권사별 수집기는 `scripts/collectors/`에서 분리한다.

원문 텍스트는 같은 저장소의 `raw-text` 브랜치(main과 히스토리를 공유하지 않음)에 리포트마다
gzip 파일(`text/{YYYY-MM}/{report_id}.txt.gz`)로 둔다. main은 요약·태그·숫자만 담아 가볍게 유지되고,
Vercel은 main만 빌드하므로 원문은 화면으로 나가지 않는다. 원문이 필요한 단계(요약, AI 평가, 숫자
추출)만 Actions에서 이 브랜치를 `raw-text/` 폴더로 함께 체크아웃한다. 로컬에서 돌릴 때는
`git worktree add raw-text raw-text`로 같은 위치에 받아 둔다.

LLM에는 원문을 그대로 넣지 않고 차트 눈금·뒤쪽 재무제표 표·고지문을 걷어 낸 본문을 넣는다
(`scripts/textprep.py`, 기존 리포트 기준 입력 약 44% 감소).

## 숫자 변화 추적

증권사마다 목표주가·투자의견을 따로 쌓고(증권사별 타임라인), 여러 증권사를 합친 컨센서스도 계산한다.

- **다른 증권사**: 한경 목록이 알려주는 종목코드·목표주가·투자의견을 먼저 쓰고, 본문 첫 장에서
  현재주가와 "직전 목표주가 X원", "기존 X원에서", "목표주가 530,000 470,000 ▲" 같은 직전 값을 읽어
  첫 리포트부터 변화를 잡는다.
- **컨센서스**: 최근 180일 안에 나온 증권사별 최신 목표주가의 평균. 변화율은 기존 증권사들의
  조정분만으로 계산해, 새로 커버를 시작한 증권사 때문에 평균이 움직인 것과 구분한다.
- **동시 움직임**: 30일 안에 증권사 3곳 이상이 같은 방향으로 목표주가를 바꾸고 반대 방향이 없으면 이벤트.

하나증권 기업 리포트에는 정해진 모양의 표가 들어 있다. `scripts/estimates.py`가 이를 정규식으로 읽는다.

| 원문 블록 | 읽는 값 |
|---|---|
| 첫 장 박스 | 투자의견(유지/상향), 목표주가(12M), 현재주가 |
| Financial Data | 증권사 자체 추정치 (`2026F`처럼 F가 붙은 연도) |
| Consensus Data | 발행 시점의 시장 컨센서스 |
| 투자의견 변동 내역 및 목표주가 괴리율 | 과거 투자의견·목표주가 이력 (산업 리포트에는 종목마다 하나씩) |

블록은 가장 가까운 앞쪽 `회사명 (123456)` 머리말의 종목에 귀속한다. 데일리 시리즈처럼 여러
기업 리포트가 이어 붙은 경우도 종목별로 나뉜다. 제목의 종목코드에 오타가 있으면 본문 코드를 믿는다.

`scripts/signals.py`는 이를 종목별 타임라인으로 합치고 직전 관측과 비교한다.
변화율은 30일 환산 속도도 함께 계산해, 같은 폭이라도 얼마나 빨리 바뀌었는지 구분한다.
임계값(`config/events.json`)을 넘으면 이벤트가 되고, 기저가 작은 값(영업이익 100억원 미만 등)과
원문 표 오기로 보이는 값은 거른다. 본문이 "목표주가 유지"라고 했는데 계산상 달라지면
(수정주가 표기 차이 등) 이벤트를 내지 않는다.

```bash
python scripts/signals.py              # 전체 재계산 (LLM 없음)
python scripts/signals.py --explain 5  # 재계산 + 이유가 없는 이벤트의 리포트 5건 설명
```
