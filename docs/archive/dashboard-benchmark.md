# 유사 리서치·시장정보 서비스 벤치마크

> 과거 설계·검토 자료다. 본문의 상태, 구현 지시, 다음 단계는 작성 당시 기준이며 현재 개발 요구사항이 아니다.
> 고도화 작업에서는 현재 코드·테스트와 새 요구사항을 확인한 뒤 필요한 내용만 참고한다.

> 조사일: 2026-10-01  
> 목적: 화면을 복제하는 것이 아니라, 리서치를 빠르게 선별하고 근거로 내려가는 상호작용 패턴을 차용한다.  
> 출처: 각 서비스의 공식 제품·도움말 페이지. 기능 명칭과 제공 범위는 구현 시점에 다시 확인한다.

## 1. 결론

비슷한 서비스들은 많은 문서를 한 화면에 그대로 보여 주지 않는다. 공통적으로 다음 순서로 정보를 압축한다.

1. **Monitor**: 저장한 관심 범위에서 새로 생긴 변화나 알림을 먼저 보여 준다.
2. **Scan**: 표·히트맵·워크스페이스에서 중요 후보를 비교한다.
3. **Inspect**: 문서 요약, 원문 구간, 이벤트 타임라인으로 근거를 확인한다.
4. **Return**: 저장된 검색·watchlist·대시보드로 같은 관점을 반복 사용한다.

우리 서비스에는 `변화 우선 홈 → 테마×산업 비교 → 근거 리포트 → URL로 같은 관점 복원`으로 적용한다.
개인용·정적 배포라는 범위 때문에 실시간 알림, 자유 배치형 워크스페이스, 시장 가격은 가져오지 않는다.

## 2. 서비스별 관찰과 차용점

### 2.1 AlphaSense — 변화 모니터링과 답변의 출처 연결

공식 페이지는 여러 문서 유형을 한 검색 환경에서 다루고, 모니터링·alerts와 생성형 검색 결과를 원문
인용에 연결하는 흐름을 강조한다.

- 참고: [AlphaSense Platform](https://www.alpha-sense.com/platform/)
- 참고: [AlphaSense Generative Search](https://www.alpha-sense.com/platform/generative-search/)

**차용**

- 홈의 첫 질문을 “전체 문서가 무엇인가?”가 아니라 **“지난번 이후 무엇이 달라졌나?”**로 둔다.
- 모든 집계 수치에서 그 수치를 만든 리포트 목록으로 내려가게 한다.
- 요약 문장과 근거 리포트를 화면상 가까이 두고, 원문 링크를 마지막 단계가 아닌 기본 동작으로 제공한다.
- 동일 애널리스트 반복을 별도 표시해 근거의 양과 다양성을 구분한다.

**차용하지 않음**

- 문서 전체를 대상으로 한 생성형 질의응답, 실시간 alert, 외부 유료 콘텐츠 통합.

### 2.2 Koyfin — 한 화면의 비교와 재사용 가능한 관점

Koyfin은 watchlist, dashboard, chart와 뉴스·시장 정보를 한 워크스페이스에서 비교하는 방식을 제공한다.
핵심은 개별 문서 페이지보다 여러 대상을 같은 열과 기간으로 비교하는 데 있다.

- 참고: [Koyfin Features](https://www.koyfin.com/features/)

**차용**

- 테마·산업 허브를 칩 모음이 아니라 **같은 열을 가진 비교표**로 만든다.
- 기간과 정렬을 한 번 선택하면 표·차트·근거 목록에 동시에 적용한다.
- 선택 상태를 URL에 보존해 동일한 관점을 다시 열고 공유할 수 있게 한다.
- 기본 화면은 고정하되 기간·필터만 조절하게 해 학습 비용을 낮춘다.

**차용하지 않음**

- 자유 배치 위젯, 다중 모니터용 워크스페이스, 개인 watchlist 편집. 현재 사용자·데이터 규모에서는
  설정 비용이 얻는 이점보다 크다.

### 2.3 Finviz — 고밀도 heatmap과 overview-to-detail

Finviz의 map은 많은 종목을 색·면적으로 압축하고, 사용자가 한 영역을 선택해 상세로 내려가는 대표적인
overview-to-detail 패턴이다.

- 참고: [Finviz Maps](https://finviz.com/map.ashx)
- 참고: [Finviz Groups](https://finviz.com/groups.ashx)

**차용**

- 테마×산업 공동 언급을 작은 셀의 heatmap으로 압축한다.
- 셀에 숫자를 직접 표시하고 클릭하면 그 셀을 구성하는 리포트만 필터링한다.
- 한 화면의 행·열을 각각 5개·8개로 제한하고, 나머지는 비교표에서 본다.

**수정해서 차용**

- 주가 등락 색을 모방하지 않는다. 색은 방향성이 아니라 **언급 밀도**만 나타낸다.
- 면적을 시장 규모처럼 보이게 하는 treemap은 사용하지 않는다. 데이터에 경제적 규모 변수가 없기 때문이다.
- 색을 볼 수 없는 사용자와 모바일을 위해 동일 데이터 표를 항상 제공한다.

### 2.4 Quartr — 이벤트 중심 탐색과 원문 맥락

Quartr는 기업 이벤트, 실적 발표 자료와 transcript를 한 맥락에서 탐색하는 경험을 제공한다. 문서를
고립된 파일보다 시간순 이벤트의 일부로 읽게 하는 점이 유용하다.

- 참고: [Quartr Web App](https://quartr.com/products/web-app)
- 참고: [Quartr Products](https://quartr.com/products)

**차용**

- 테마 상세에 최초 등장일, 최근 등장일, 활성 주 수를 보여 준다.
- 주차별로 핵심 주장 → 근거 리포트 → 리스크를 읽는 타임라인을 둔다.
- 다음 주 체크포인트는 문단이 아니라 날짜순 이벤트 목록으로 표시한다.

**차용하지 않음**

- 음성·transcript 동기화, 기업 IR 캘린더 전체, 모바일 푸시.

### 2.5 Feedly — 관심 범위의 신호화와 중복 억제

Feedly는 여러 소스를 피드로 모으고, 관심 주제와 우선순위에 따라 모니터링하는 방식을 제공한다.
수집량이 늘어날수록 새 항목과 중복·저가치 항목을 구분하는 패턴이 중요해진다.

- 참고: [Feedly Market Intelligence](https://feedly.com/market-intelligence)
- 참고: [Feedly AI](https://feedly.com/ai)

**차용**

- 신규·확대·지속·약화를 명시해 단순 최신순 목록보다 변화 신호를 먼저 제공한다.
- `daily_series`를 빈도 집계에서 제외하고 동일 리포트 내 중복 태그를 한 번만 세어 중복을 억제한다.
- 이후 알림을 도입하더라도 모든 새 문서가 아니라 관심 테마의 신규·확대만 후보로 삼는다.

**차용하지 않음**

- 불투명한 AI 중요도 점수와 사용자별 자동 우선순위. 현재는 절대 건수와 근거 목록이 더 검증 가능하다.

## 3. 공통 패턴을 우리 화면에 적용

| 검증된 패턴 | 우리 구현 | 기대효과 | 우선순위 |
|---|---|---|---:|
| 변화/alert 우선 | 홈 `무엇이 달라졌나` | 읽을 주제를 먼저 선별 | P0 |
| 동일 기준 비교 | 테마·산업 비교표 | 누적량과 최근 변화를 구분 | P0 |
| overview-to-detail | heatmap 셀 → 필터된 리포트 | 파급 관계에서 근거로 이동 | P0 |
| source traceability | 모든 숫자에 report ID 집합 | 요약의 검증 가능성 확보 | P0 |
| 저장 가능한 관점 | URL 기반 기간·필터·정렬 | 반복 방문과 공유 비용 감소 | P0 |
| 이벤트 타임라인 | 테마 주차별 주장·근거·리스크 | 점이 아닌 흐름으로 학습 | P1 |
| progressive disclosure | 2줄 요약 → 펼침 → 원문 | 첫 화면 텍스트 밀도 감소 | P0 |
| 관심 범위 재방문 | 관심 테마 저장 | 반복 모니터링 | P2 |

## 4. 차용하지 않을 패턴

### 4.1 가격 터미널처럼 보이는 화면

현재 데이터에는 시장 가격이나 경제적 가중치가 없다. 빨강·초록, 상승 화살표, treemap 면적을 쓰면
리포트 언급량을 투자 성과나 시장 규모로 오해하게 한다. 상태 라벨과 `리포트 언급량` 문구를 우선한다.

### 4.2 설정 가능한 위젯부터 만드는 것

개인화 대시보드는 데이터와 과업이 안정된 뒤 유용하다. MVP는 한 가지 권장 읽기 순서를 제공해 어떤
정보가 실제로 쓰이는지 먼저 확인한다.

### 4.3 AI 답변을 근거보다 앞세우는 것

현재 강점은 이미 생성된 요약과 리포트 간 연결이다. 새로운 대화형 답변보다 숫자·요약·원문 사이의
추적 가능성을 먼저 완성한다.

### 4.4 모든 항목에 알림을 보내는 것

알림은 이번 범위가 아니다. 추후에도 신규·확대 상태와 사용자가 명시적으로 저장한 관심 테마를 함께
만족할 때만 후보로 삼아 알림 피로를 막는다.

## 5. 구현에 반영할 결정

1. 홈 최상단은 상태 바 다음에 `무엇이 달라졌나`를 배치하고, 긴 주간 설명보다 먼저 보이게 한다.
2. 변화 행과 heatmap 셀에는 항상 `근거 보기` 동작을 제공한다.
3. 테마·산업 허브는 누적 칩을 비교표로 교체한다.
4. 테마 상세에 `최초 등장 / 최근 등장 / 활성 주`와 주차별 타임라인을 추가한다.
5. URL을 저장 가능한 workspace로 취급해 기간·필터·정렬을 복원한다.
6. 시각화의 색은 언급 밀도·상태만 표현하며 가격 방향처럼 보이는 범례를 쓰지 않는다.
7. 개인화·알림·자유 위젯은 MVP 결과가 검증되기 전까지 구현하지 않는다.

## 6. 검증 질문

구현 후 다음 질문으로 차용 효과를 검증한다.

- 사용자가 긴 주간 설명을 읽기 전에 신규·확대 테마를 찾는가?
- heatmap에서 관계를 찾은 뒤 실제 근거 리포트까지 이동하는가?
- 누적 건수가 큰 테마와 최근 확대된 테마를 구분하는가?
- URL을 다시 열었을 때 같은 분석 관점이 복원되는가?
- 언급 밀도를 주가 상승·투자 매력으로 오해하지 않는가?
