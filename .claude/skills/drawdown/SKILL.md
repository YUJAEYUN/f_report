# 급락 국면 종합 (대화형)

파이프라인용 명세 `skills/synthesize-drawdown/SKILL.md`를 도구가 있는 세션에서 따르는 절차다.
자동 실행(drawdown-synthesis 워크플로)과 같은 형식의 결과를 만들되, 사용자 메모를 넣고
`확인할 것`을 웹 검색으로 채운다는 점이 다르다.

## 절차

1. **날짜 정하기**: 사용자가 말한 날짜, 없으면 오늘(KST).
2. **메모 받기**: 사용자가 내부 자료를 읽고 던지는 메모를 그대로 받는다. 정리를 요구하지 않는다.
   받은 메모는 `notes/{날짜}.md`에 저장한다(`notes/`는 git에 올라가지 않는다). 메모가 없으면 건너뛴다.
3. **재료 묶기**:
   ```bash
   python scripts/drawdown.py --date {날짜} --memo notes/{날짜}.md --dump tmp/drawdown-{날짜}.md
   ```
   메모가 없으면 `--memo`를 뺀다. 감지 결과(급락 신호 건수)를 사용자에게 한 줄로 알린다.
4. **분석**: `tmp/drawdown-{날짜}.md`를 읽고 그 안의 SKILL 명세대로 쓴다. 대화형이므로
   - `확인할 것`에 오를 숫자·사실(지수 종가, 사이드카 시각, 환율, 지표 발표치)은 웹 검색으로 확인해 본문에 반영하고,
     확인한 출처를 `## 근거 리포트` 아래 `- 확인 출처: [제목](URL)`로 붙인다.
   - 메모 문장을 검색어에 그대로 넣지 않는다. 검색어는 공개된 사실로만 만든다.
   - 메모의 주장이 리포트와 부딪히면 감추지 말고 `논리 점검`에 쓴다.
5. **쓰기와 검사**: 결과를 `insights/drawdown/{날짜}.md`에 쓰고 형식을 검사한다.
   ```bash
   python scripts/drawdown.py --check insights/drawdown/{날짜}.md
   ```
6. **전달**: 한 줄 결론과 가장 중요한 반증 조건 하나를 대화에 쓰고, 핀포인트 질문이 있으면 함께 묻는다.
   사용자가 답하면 해당 섹션만 고친다. 커밋은 사용자가 원할 때만 한다.

## 주의
- 메모 내용은 `insights/drawdown/{날짜}.md`에 "작성자 메모에 따르면"으로 들어간다. 이 파일은 커밋 대상이므로,
  커밋 전에 내부 자료가 그대로 옮겨진 문장이 없는지 사용자에게 확인받는다.
- 매수·매도 권유를 쓰지 않는다.
